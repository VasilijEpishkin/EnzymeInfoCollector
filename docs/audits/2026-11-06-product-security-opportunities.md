# EnzymeInfoCollector — анализ продукта, корректности и безопасности

Дата: 6 ноября 2026. Основа: код main после PR #28, существующие тесты, результаты validation v1 / phases 2–3 и ограниченный аудит источников/экспорта. Это не внешняя пенетрационная проверка и не экспериментальная валидация ферментативной активности.

## Для кого инструмент может быть полезен

- **Биоинформатики и кураторы данных:** проверять реальные UniProt protein→Rhea утверждения, направленные ECO/публикации и происхождение химических участников; находить неподтверждённые связи и расхождения источников.
- **Исследователи ферментов и metabolic engineering:** быстро изучать ограниченную выборку изоформ/ортологов перед ручной проверкой субстратов, структуры и кинетики. Результат — отправная точка для гипотез, НЕ лабораторное подтверждение.
- **Разработчики научных пайплайнов:** получать JSON/GraphML/Cytoscape с typed provenance, ChEBI identity и коэффициентами для дальнейшего анализа.
- **Образование:** демонстрировать различие EC-классификации и прямой аннотации, Rhea equation side и физиологического направления, известного и отсутствующего evidence.

Это предполагаемые сценарии полезности, а не подтверждённая статистикой аудитория или доказанный спрос.

Сначала добавить диагностический отчёт со списком unsupported; частичные химические графы — только с явно маркированной неполнотой и тестами |

## Что НЕ установлено

- Не обнаружен и не заявляется подтверждённый удалённый exploit, SQL injection или XSS. Локальный просмотрщик использует textContent и ограничения на типы связей; это полезные меры, но не доказательство абсолютной безопасности.
- Не выполнялась полномасштабная нагрузочная проверка больших UniProt наборов, доступности на мобильных устройствах или балансировки атомов для всех Rhea реакций.
- Валидация на 20 записях измеряет точность извлечения данных из UniProt для этих записей, а не экспериментальную точность выявления функций белков.
- Уязвимость pickle предполагала бы возможность подмены промежуточного локального файла. По умолчанию TemporaryDirectory создаёт отдельный временный каталог; оценка риска не равна доказательству удалённого исполнения кода.

## Рост: решения по ценности и готовности

| Приоритет | Практический результат | Критерий завершения |
| --- | --- | --- |
| P0, выполнено | Выбор одного UniProt accession после предпросмотра нескольких белков | Preview с белком/генами, bounded selection, pinned SHA, fail-closed и end-to-end live example (PR #28) |
| P0, безопасность | Отсутствие pickle.load на управляемых приложением временных данных | JSONL merge, потоковый bounded sort, unicode/invalid JSONL regression, полная offline CI |
| P1 | Краткая сводка качества аннотаций для пользователя | Читаемый отчёт: белок, direct Rhea, ECO/PMID, unresolved chemistry, origin, source drift, без биологических оценок «хороший/плохой» |
| P1 | Диагностика неполных реакций без потери остальных проверенных результатов | Strict по умолчанию; отдельный opt-in report с явно listed unsupported, source/provenance, и тестами отсутствия вымышленных соединений |
| P1 | Понятное предупреждение legacy-CLI о EC-группировке | Не менять JSON/CSV schema; CLI и README отличают EC-classification vs direct UniProt→Rhea evidence |
| P2 | Воспроизводимые исследовательские наборы | Snapshot/manifest с хэшами реальных source bytes, refresh/drift status, без выдачи хэша за официальный release |
| P2, зависимость от спроса | SABIO-RK/BRENDA как отдельные контекстные измерения | Пилот на 5 EC классах, единицы Km/kcat, pH, T, организм и license/provenance; **не соединять** измерение с accession без подтверждённого identity match |

## Как проверять следующий релиз

1. Сохранять различие candidate vs direct assertion в интерфейсе и CLI; не использовать EC для прямого Protein→Reaction join.
2. Проверять на реальном входе с несколькими изоформами/генами, не на одном положительном P04040.
3. Проверять no-direct, unsupported RDF, изменённый поисковый SHA и случай ограниченной выдачи как явные состояния, не как пустую «биологию».
4. Выполнять Python 3.11/3.13 offline CI + Node/Chrome checks и отдельно bounded live smoke, поскольку HTTP 503 источника не является ошибкой парсинга.
